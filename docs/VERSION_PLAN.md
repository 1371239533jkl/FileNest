> 版本划分规则：**每个批次对应一个版本号**，批次完成即发版。
> 语义化版本：主版本.次版本.修订 —— 功能批次用次版本号递增；平台化/破坏性变更升主版本。
> 每发一版同步：① `config.py` 的 `APP_VERSION` ② git 标签 `vX.Y.Z` ③ GitHub Release 说明。

## 版本号划分逻辑

- **v2.2.0 ~ v2.4.0（已完成批次）**：P0 核心能力补齐，从 v2.1.0 基线逐批递增次版本号
- **v2.5.0 ~ v2.7.0（待执行批次）**：P1 增值能力，继续递增次版本号
- **v3.0.0（批次 7）**：P2 平台化涉及新基础设施与架构演进，升主版本
- 批次内的小修（bug fix、UI 微调）不打新版本，随所在批次发版；如有紧急修复需单独发版，用修订号递增（如 v2.4.1）

## 发版操作清单（每个批次完成后）

1. 更新 `config.py` 中 `APP_VERSION` 为新版本号
2. 运行测试确认通过（`python -m pytest tests`）
3. git 提交版本号变更
4. 打标签：`git tag vX.Y.Z`
5. 推送：`git push origin main --tags`
6. 在 GitHub 创建 Release，说明该批次交付的功能清单
